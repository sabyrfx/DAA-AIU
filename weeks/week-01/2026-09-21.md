## Today's work

### 1. SWAP(a, b)

`SWAP(a, b)` exchanges the values of two variables.

```text
temp = a
a = b
b = temp
```

A temporary variable is needed so the original value of `a` is not lost.

- Time complexity: **O(1)**
- Auxiliary space: **O(1)**

The number of operations does not depend on input size.

---

### 2. Time complexity

Time complexity describes how the amount of work performed by an algorithm grows as the input size `n` grows.

It is not primarily about seconds. We analyze how many basic operations are executed relative to `n`.

Common examples:

| Complexity | Meaning |
|---|---|
| O(1) | Constant |
| O(log n) | Logarithmic |
| O(n) | Linear |
| O(n log n) | Linearithmic |
| O(n²) | Quadratic |
| O(2ⁿ) | Exponential |

---

### 3. Frequency-count example: SUM(A, n)

```text
Algorithm SUM(A, n)
{
    s = 0

    for (i = 0; i < n; i++)
    {
        s = s + A[i]
    }

    return s
}
```

The loop visits every element once.

A simplified operation count used in class:

```text
s = 0              -> 1
loop condition     -> n + 1
loop body          -> n
return s           -> 1
```

Therefore:

```text
T(n) = 1 + (n + 1) + n + 1
     = 2n + 3
```

For asymptotic analysis, constants do not change the growth class:

```text
T(n) = 2n + 3 -> O(n)
```

Important: depending on exactly which primitive operations are counted, the exact formula can differ, but the Big O can remain the same.

---

### 4. Big O notation

Big O describes the growth rate of an algorithm as `n` becomes large.

For example:

```text
2n + 3
10n + 500
1000n + 1
```

are all **O(n)** because they grow linearly.

When finding the dominant growth class, constant multipliers and lower-order constant terms are ignored.

---

### 5. Space complexity

Space complexity describes how memory usage grows with input size.

Two useful ideas:

- **Input space**: memory already occupied by the input.
- **Auxiliary space**: additional memory created by the algorithm.

For `SUM(A, n)`:

- Input array `A` contains `n` elements -> input space **O(n)**
- The algorithm only needs variables such as `s` and `i` -> auxiliary space **O(1)**

So the usual analysis is:

- Time: **O(n)**
- Auxiliary space: **O(1)**

If total memory including the input is counted, the total space is **O(n)**.

### 6. ADD(A, B, n) for matrices

For two `n x n` matrices, matrix addition adds corresponding elements.

```text
Algorithm ADD(A, B, n)
{
    create C[n][n]

    for (i = 0; i < n; i++)
    {
        for (j = 0; j < n; j++)
        {
            C[i][j] = A[i][j] + B[i][j]
        }
    }

    return C
}
```

There are two nested loops:

```text
n * n = n²
```

Therefore:

- Time complexity: **O(n²)**
- Auxiliary space if a new result matrix `C` is created: **O(n²)**
- Auxiliary space if one input matrix is modified in place: **O(1)**

The key reason is that an `n x n` matrix contains `n²` elements and matrix addition must process each one.

---

## Main analysis workflow

For an algorithm, ask:

1. What is the input size `n`?
2. What is the basic operation?
3. How many times is it executed?
4. What is the resulting `T(n)`?
5. What is the dominant growth term -> Big O?
6. How much additional memory is created?
7. What are the time and auxiliary-space complexities?
